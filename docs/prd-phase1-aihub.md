## 1. 背景与目标

### 1.1 背景

AI 工具与开源项目迭代快，爱好者需要一个轻量入口，用来发现值得关注的项目与热点，而不是再做一个社区、评测站或对话产品。

AiHub 定位为 **AI 导航站**：聚合并展示公开来源上的 AI 相关项目与热点，帮助用户快速浏览并跳转到原始站点深入了解。

### 1.2 一期目标

一期同时服务两个用户意图：

1. **发现项目**：在提示词 / MCP / Skills 等品类中浏览条目，并跳转到来源页。
2. **看资讯（热点）**：在 **AI 前沿** 中分别浏览 GitHub 热点与 Product Hunt 热点。

### 1.3 成功样子（产品层）

架构师与研发读完本文后，应能据此完成一期范围对齐，并明确：

- 站点有哪些一级栏目、各栏目职责边界；
- 展示哪些内容对象与字段语义；
- 哪些能力明确不做；
- 内容从哪些公开来源进入站点（产品原则，非实现）。

一期对终端用户的直观成功标准：用户能在站内完成「浏览列表 → 按热度/最新排序 → 点击外链」的闭环，且 AI 前沿中 GitHub 与 Product Hunt 分区清晰可辨。

## 2. 用户与场景

### 2.1 目标用户

**AI 爱好者**：关注新工具、开源项目、提示词、MCP、Skills 及行业热点，以浏览与跳转外链为主，不要求注册或生产内容。

### 2.2 核心场景

| 场景 | 用户行为 | 一期期望结果 |
|---|---|---|
| 逛品类库 | 进入 AI 提示词 / MCP / Skills，浏览条目 | 看到名称、简介、链接与热度指标，可排序 |
| 看热点 | 进入 AI 前沿，分别看 GitHub / Product Hunt | 两区独立展示，可按热度或最新排序 |
| 跳出深读 | 点击感兴趣条目 | 前往 GitHub 或 Product Hunt 等来源站 |
| 从首页出发 | 打开站点 | 能进入各一级栏目（首页具体内容另案） |

### 2.3 非场景（一期）

- 注册登录、收藏对比、评论讨论
- 在站内阅读全文或使用生成式对话
- 提交/评审项目、参与社区运营

---

## 3. 产品范围（含非目标）

### 3.1 一期范围内

- 五栏信息架构：首页、AI 提示词、MCP、Skills、AI 前沿（详见 §4）
- 列表浏览、来源侧热度展示、热度/最新排序、外链跳出
- AI 前沿内 GitHub 与 Product Hunt **分开展示**，并预留二级标签
- 内容来自公开 GitHub 资料，以及公开网页上的 Product Hunt 资料（详见 §7）
- 无账号下的纯展示体验

### 3.2 一期非目标（明确排除）

- 社区（关注、帖子、讨论区等）
- 评测 / 打分体系
- 生成式对话或站内 AI 助手
- 账号体系及一切登录态能力（收藏、点赞、评论、个人中心等）
- 全站搜索、站内详情页、原文转载
- 自研「综合热度分」（只用 Star / Upvote 等来源原生指标）
- 首页具体视觉与物料方案（另案）
- 二期及以后的栏目扩展、多来源扩展（除已列待决项）

### 3.3 版本边界

本文档 **只覆盖一期**。二期展望不在正文展开；未决事项见 §9。

## 4. 信息架构与栏目

### 4.1 主导航

一期站点主导航固定为以下五个入口（顺序如下）：

1. **首页**
2. **AI 提示词**
3. **MCP**
4. **Skills**
5. **AI 前沿**

架构与研发应以上述五栏作为站点一级信息架构；栏目增删不属于一期范围。

### 4.2 首页（一期边界）

- 首页是进入站内的默认落地页，须能导向上述各栏目。
- 首页的具体内容编排、物料与视觉表现（含「酷炫」呈现）**不在本 PRD 锁定**，由首页专项另行定义。
- 本 PRD 对首页的一期要求仅到：**可进入站内、可到达各一级栏目**。

### 4.3 AI 前沿

- 承担一期「看资讯 / 看热点」需求（不另设「AI 资讯」栏目）。
- **GitHub 热点**与 **Product Hunt 热点**分开展示（两个并列分区或两个明确入口，不得混在同一无区分列表中）。
- Product Hunt **仅出现在 AI 前沿**，不进入提示词 / MCP / Skills。
- 支持 **二级标签**（用于分区内筛选或归类）；一期允许标签枚举先占位，但信息架构须预留该能力。
- 列表须可浏览；默认按来源侧热度指标排序（GitHub：Star；Product Hunt：Upvote），并提供按「最新」排序的切换。
- 不提供站内详情页：点击条目跳转至来源站（GitHub 或 Product Hunt）；本站不承载原文正文。

### 4.4 AI 提示词 / MCP / Skills

- 三个独立栏目，各自为独立列表页。
- 浏览形态：条目卡片/列表（名称、简介、链接、热度指标可见即可），具体视觉不锁死。
- 外链以公开项目页为主（通常为 GitHub）；点击跳出至来源站，一期不做站内详情页。
- 默认按 Star（或该来源等价热度指标）排序，并提供「最新」排序切换。
- **内容来源站点一期尚未选定**：栏目与字段约定仍须落地；来源未定时，页面允许空态/占位说明，不得因此取消栏目。

### 4.5 一期明确不做的站内能力（信息架构层）

- 全站搜索
- 站内详情页 / 原文转载页
- 页脚「关于我们」等运营页（非导航必需）
- 账号、收藏、评论等互动入口

### 4.6 跨端与列表完整性

- 一期须在常见桌面与移动宽度下可完成「浏览列表 + 跳出外链」；不要求与桌面完全同构的复杂布局。
- 列表须支持用户浏览到完整结果集（分页或加载更多等交互形态不锁死）。

## 5. 内容对象与字段语义

一期所有可列表展示的条目，统一遵循下列**最小字段语义**（命名可在实现时映射，产品含义不可丢）。

### 5.1 通用条目字段

| 字段（产品语义） | 说明 | 必填 |
|---|---|---|
| 名称 | 条目对外展示标题 | 是 |
| 简介 | 一句话或短段落说明用途/内容 | 是 |
| 链接 | 跳转到来源站的 URL（品类页多为 GitHub；前沿按来源分别为 GitHub 或 Product Hunt） | 是 |
| 来源类型 | 标识条目来自 GitHub 或 Product Hunt 等（品类页在来源未定时可先预留） | 是（有来源后） |
| 热度指标 | 来源原生指标：GitHub 为 Star；Product Hunt 为 Upvote | 有来源数据时必有 |
| 时间 | 用于「最新」排序的时间语义（如发布/抓取可见时间，产品层不规定技术字段名） | 支持「最新」排序时必有 |
| 二级标签 | 主要用于 AI 前沿分区内筛选/归类；品类页一期可选 | AI 前沿预留；品类页可选 |

### 5.2 热度规则

- **不设**站内自研综合热度分。
- GitHub 条目展示并按 **Star** 参与默认排序。
- Product Hunt 条目展示并按 **Upvote** 参与默认排序。
- 禁止把 Upvote 与 Star 混称为同一指标或直接数值横比。

### 5.3 分栏目对象说明

| 栏目 | 对象理解 | 链接倾向 |
|---|---|---|
| AI 提示词 | 可发现的提示词相关公开条目 | 多为 GitHub；最终以来源站为准 |
| MCP | MCP 相关公开条目 | 多为 GitHub |
| Skills | Skills 相关公开条目 | 多为 GitHub |
| AI 前沿 · GitHub | GitHub 热点项目 | GitHub 项目页 |
| AI 前沿 · Product Hunt | Product Hunt 热点产品 | Product Hunt 产品页 |

## 6. 核心体验（发现 / 浏览 / 排序）

体验参考 **Product Hunt** 的「发现流」气质：以列表发现为主，强调热度与新鲜度，点击去源站，不在本站沉淀社区互动。

### 6.1 发现

- 用户通过主导航进入栏目，即可看到条目列表。
- AI 前沿必须让用户一眼区分 GitHub 区与 Product Hunt 区。

### 6.2 浏览

- 每个条目至少可见：名称、简介、热度指标、可点击链接。
- 二级标签在 AI 前沿可用时，应能缩小当前分区内的浏览范围。
- 列表需可浏览完整集合；空态须可读（尤其是品类来源未定时）。

### 6.3 排序

- 默认：按该来源热度指标降序（Star 或 Upvote）。
- 可选：按「最新」排序。
- 一期不要求更复杂的个性化推荐。

### 6.4 跳出

- 点击条目进入来源站；本站不提供详情页与原文正文。
- 用户应能理解「AiHub 是导航/发现层，深度内容在源站」。

## 7. 内容来源与同步原则

### 7.1 原则（产品语义）

- 一期内容来自 **公开可访问** 的外部资料，在站内做导航式展示。
- 已确定的来源范围：**GitHub** 与 **Product Hunt**。
- Product Hunt 资料仅用于 **AI 前沿**。
- 系统应能 **持续同步** 并更新列表展示；本文不描述同步实现方式。
- 已删除早期设想中的「agent 自动运营」表述；一期不以「智能体代运营」作为产品定义。

### 7.2 分栏目来源

| 栏目 | 一期来源 |
|---|---|
| AI 前沿 · GitHub | GitHub 公开热点/项目资料 |
| AI 前沿 · Product Hunt | Product Hunt 公开网页资料 |
| AI 提示词 / MCP / Skills | **待决**：需选定公开热门站点；未定前可空态，但栏目保留 |

### 7.3 合规与展示边界（产品层）

- 只展示导航所需摘要信息（名称、简介、指标、链接等），不在站内完整转载源站正文。
- 热度数字以来源站为准展示，不在站内改写为自有评分。

## 8. 一期验收标准

以下为产品验收口径（供架构/研发对齐范围，不代替测试用例细节）。

1. **导航**：五个一级入口均可到达；无账号体系入口。
2. **首页**：可进入站内并到达各栏目；不验收首页酷炫视觉专项（另案）。
3. **AI 前沿**：GitHub 与 Product Hunt 分开展示；可见热度指标；支持热度默认排序与「最新」排序；点击跳转对应源站；二级标签能力已预留（枚举可先占位）。
4. **品类三页**：AI 提示词 / MCP / Skills 页面存在；字段按 §5 可展示；来源未定时空态可接受。
5. **体验边界**：无搜索、无详情页、无社区/评测/对话/登录。
6. **列表**：用户可浏览到完整结果集；桌面与移动宽度下可完成浏览与外链跳出。
7. **热度**：无站内综合热度分；Star 与 Upvote 不混用。

## 9. 待决与一期不覆盖项

### 9.1 待决（需产品确认后再锁）

1. **AI 提示词 / MCP / Skills 的公开来源站点**（各选哪个热门公开站，或是否共用同一来源）。
2. **AI 前沿二级标签的具体枚举**（一期可先占位，上线前需定一版可用标签）。
3. **首页专项**：内容编排与视觉方案（本 PRD 只要求可导航）。
4. **列表条数与更新频率的产品预期**（例如「前沿各区至少展示多少条」「用户感知的新鲜程度」）——若验收需要数字，另行确认。

### 9.2 一期明确不覆盖

- 二期栏目、多语言、个性化推荐、消息通知
- 用户生成内容（UGC）与投稿审核流
- 商业化（广告位、付费榜等）
- 除 GitHub、Product Hunt 以外的新来源接入（品类来源选定除外）
